# Ограниченный Автономный Workflow

Этот документ описывает допустимую автономность для проекта.

**TL;DR — нужен ли отдельный LLM-агент, запускающий команды? Нет.**
Решения здесь детерминированы (см. Decision Matrix в [AGENT_GUIDE.md](AGENT_GUIDE.md)),
поэтому действия выполняет **cron**, а LLM лишь **генерирует тексты** писем и ответов
([LLM_SETUP.md](LLM_SETUP.md)). Агент-оркестратор с правом запуска команд только добавляет
риск (массовые отправки, новый `search` сразу в live) без выигрыша.

Главная мысль:

- автономно можно крутить повторяемые safe-операции;
- нельзя делать бесконтрольный live-контур с массовыми ответами и новым поиском без review.

## Что Считать Нормальной Автономностью

Допустимо автоматизировать:

- `refresh-token`
- `update-resumes`
- `apply-vacancies` с заранее проверенным набором параметров
- сбор логов и digest для последующего анализа

Нежелательно fully-auto:

- `reply-employers`
- follow-up в старых чатах
- новые search-контуры без `dry-run`

## Базовый Цикл

1. Проверить `preflight`
2. Обновить токен при необходимости
3. Запустить `update-resumes`
4. Запустить safe `apply-vacancies`
5. Считать `digest`
6. Если нужно, отдельно выполнить `review-negotiations`

## Обязательные Ограничения

- Новый поиск сначала идёт только в `dry-run`
- Переговоры не отправляются массово без review
- Если токен сломан и refresh невозможен, цикл останавливается
- Если выдача стала нерелевантной, live-запуск отменяется

## Наблюдаемость

Для каждого цикла должно быть видно:

- какие команды запускались;
- сколько вакансий найдено;
- сколько откликов реально отправлено;
- есть ли ошибки авторизации или AI;
- есть ли переговоры, требующие внимания.

## Разделение Ответственности

- `cron` отвечает за запуск
- `hh-applicant-tool` отвечает за deterministic выполнение
- `AI` помогает, но не является источником безусловных действий
- `человек или supervisory-agent` меняет стратегию
