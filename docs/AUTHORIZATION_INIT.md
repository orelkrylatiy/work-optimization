# Авторизация И Первый Запуск

## Как Это Работает

Для операций, которым нужен доступ к HH:

1. приложение ищет `access_token` в `config.json`
2. если access token истёк, пытается использовать `refresh_token`
3. если токенов нет или refresh невозможен, требуется ручная авторизация

## Основные Команды

```bash
hh-applicant-tool authorize
hh-applicant-tool whoami
hh-applicant-tool refresh-token
```

`whoami` удобен как быстрый smoke-check после первого логина.

## Что Требует Человека

Первичная авторизация:

- логин
- код подтверждения
- иногда капча

Это не стоит пытаться полностью автоматизировать.

## Где Хранятся Токены

В директории профиля:

- `config.json`
- `cookies.txt`

В Docker-сценарии по умолчанию это `/app/config`.

## Что Делать После Первого Логина

1. проверить `whoami`
2. проверить `list-resumes`
3. сделать `apply-vacancies --dry-run`
4. только потом включать cron или VPS automation

## Ошибки Авторизации

- токен истёк, но есть `refresh_token` -> использовать `refresh-token`
- токенов нет -> нужна `authorize`
- refresh сломан -> нужна повторная ручная авторизация
